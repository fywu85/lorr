# General bounded unopened-matching cadence

The existing unopened-task matching pass runs once every ten steps. The optional `CGAR_REASSIGN_MATCH_INTERVAL` selects a fixed interval from 1 to 100; missing or explicit 10 preserves prior behavior. A nondefault interval requires enabled matching. This mechanism uses observed tasks, robot states and the existing metric; it adds no map identity test or template. Native Warehouse experiments still require `--trick WAREHOUSE` for their existing field and cutoff policy.

The first planned comparison is **10 versus 5 steps**, not every-step unlimited rematching. Every pass retains the existing 64-group profile quota, 32-robot groups, bounded BFS, complete resident-only tables and full matching solve. The same primary/next-primary/recovery/commitment/fair/started/at-pickup protections, one retarget per task and 20-step robot cooldown apply. More frequent passes increase prescribed work per run; this is a scheduling-policy test, not an equal-work speedup claim. Earlier matching might avoid pickup travel, but it can consume a task's sole retarget earlier or change traffic adversely.

The read-only budget-shadow stride must be divisible by the configured real matching interval. Fresh-audit ordinary-versus-matching-tick accounting also follows that interval. No default trace or logging change is intended; only a nondefault interval emits the new cadence receipt.
